# Fiknova × MoneyPrinterTurbo

مسار عملي لإنتاج **مسودة فيديو عربية للمراجعة** من نص معتمد ومواد أصلية. يسمح بمقاطع أداة فعلية أو محاكاة تعليمية موسومة بوضوح؛ لا تقدم المحاكاة باعتبارها تسجيلًا لأداة. يحتفظ ملف الحلقة بالعنوان والوصف والنص الإنجليزيين لتجهيز التوطين لاحقًا، ولا يولّد دبلجة إنجليزية أو ينشر على YouTube.

## البدء

1. جهّز تشغيل المشروع في [Codespaces](../docs/CODESPACES-AR.md) على الفرع الذي يحتوي على هذا المسار، أو في حاوية Docker الخاصة. ضع إعدادات الخدمات في `config.toml` (أو في `MPT_CONFIG_FILE`). يجب أن يبقى `upload_post_auto_upload = false` في قسم `[app]`.
2. انسخ [مثال الحلقة الثانية](episodes/ep02.sample.json) إلى ملف عمل خاص بك. استخدم مثال اجتماع **افتراضي** وخطوات شاشة حقيقية من إنتاجك، من دون بيانات عمل حساسة. ضع مقطعي العرض عند المسارين المحددين في `materials`، أو عدّل المسارات إلى ملفاتك الأصلية. ابدأ بلقطة النتيجة ثم اعرض الانتقال من الملاحظات إلى القرارات والمهام. لا يكفي مشهد عام عن اجتماع لإثبات الخطوات.
3. راجع صحة النص، التسلسل، ادعاءات الأداة، المقاطع، والحقوق. غيّر `status` من `draft` إلى `approved` بعد اعتماد المحتوى للإنتاج؛ هذا الاعتماد لا يجيز النشر.
4. شغّل من جذر المستودع:

   ```bash
   uv run --no-sync python fiknova/pipeline.py plan fiknova/episodes/ep02.sample.json
   uv run --no-sync python fiknova/pipeline.py render fiknova/episodes/ep02.sample.json
   ```

`plan` يعرض المواد والخط والإعدادات الناقصة. `render` يستخدم CLI المشروع لتكوين الصوت السعودي والترجمة العربية والفيديو العمودي `9:16` ثم يحفظ `review.json` و`render.log` داخل `storage/fiknova/<id>/`. تُحفظ ملفات MP4 النهائية في `storage/tasks/<task_id>/`؛ تجد مسارها في `review.json`.

مقاطع الشاشة أصلية وبترتيب ثابت، والتعليق الصوتي `ar-SA-HamedNeural`. الموسيقى متوقفة إلى حين توفير مادة مرخصة. يعمل النص المعتمد دون مفتاح LLM، وتعمل المواد المحلية دون مفتاح مكتبة مقاطع. يحتاج الصوت إلى اتصال بخدمة TTS، وتحتاج النسخة الإنجليزية لاحقًا إلى مراجعة تحريرية وتسجيل/دبلجة مستقلين.

قبل نشر أي فيديو، افحص أول ثانيتين، تطابق الصوت مع اللقطات، قراءة الترجمة على الهاتف، صحة القرارات والمواعيد وعدم ظهور بيانات خاصة، ثم عنوان وصورة الفيديو. الاختبار التقني لتوليد MP4 لا يثبت جودة التجربة التحريرية.

**قيود التشغيل:** لا يُضاف هذا المسار إلى جدول نشر تلقائي. خدمة Upload-Post العامة في المشروع قد تنشر بعد توليد الفيديو إذا فُعّلت؛ لذلك يرفض هذا المسار التشغيل عندما لا يثبت أن `upload_post_auto_upload = false`. لا تضع مفاتيح أو مواد خاصة في GitHub؛ مجلد `storage/` مستبعد من التتبع.

## التجربة التعليمية للحلقة الثانية

أضيفت بيانات اجتماع افتراضي في `ep02_meeting.sample.json`: قرار واحد، مهمتان، وأربعة عناصر للتحقق. لكل مخرج مرجع إلى ملاحظة أصلية. موعد عمر غير محدد، ومبلغ 50 ألف ريال وموعد 1 نوفمبر مقترحان غير معتمدين. خطأ الموعد في المشهد التعليمي **مصمم للتوضيح، وليس ناتجًا مرصودًا لأداة**. عُدّل النص العربي والإنجليزي ليتوافق مع هذا الإفصاح؛ بقيت الحالة `draft`.

لإعادة إنشاء المواد، ثبّت Pillow مع دعم RAQM، ووفر FFmpeg وFFprobe وخط `resource/fonts/NotoNaskhArabic-Regular.ttf` (متوافر في صورة Docker الخاصة بالمشروع)، ثم شغّل من الجذر:

```bash
python fiknova/prepare_ep02_demo.py
python fiknova/pipeline.py plan fiknova/episodes/ep02.sample.json
```

الأداة المحلية لا تستدعي AI أو TTS، ولا تعتمد الحلقة أو تنشرها. تنشئ مقطعي `fiknova/assets/ep02-notes-demo.mp4` و`ep02-output-demo.mp4`، كل منهما 32 ثانية، ونسخة `storage/fiknova/ep02-preparation/Fiknova_EP02_Visual_Review.mp4` مدتها 64 ثانية بدقة 1080×1920، صامتة وموسومة بأنها محاكاة ومسودة. هذه نسخة بصرية مستقلة لمراجعة التسلسل واللغة؛ ليست ناتج `pipeline.py render` ولا تثبت سلوك نموذج AI فعلي.

يبدأ المقطع الأول بلقطة النتيجة، ثم الملاحظات وطلب الاستخراج. يعرض الثاني الخطأ المصمم والتصحيح وقائمة التحقق والمراجعة البشرية. يمكن إيقاف الفيديو مؤقتًا لفحص التفاصيل.

إعداد `video_clip_duration = 64` في مثال الحلقة يحافظ على المقطعين كاملين؛ إعداد المحرك السابق البالغ 5 ثوانٍ كان سيأخذ بداية كل مقطع فقط عند استخدام `sequential`. ينسخ `render` المواد بعد اجتياز بوابات الاعتماد والخط والإعدادات إلى `storage/local_videos/fiknova/<id>/`، لأن المحرك يرفض مسارات المواد خارج `storage/local_videos`. لم تُخفف حماية المحرك أو بوابة الاعتماد.

فحص `plan` يختبر وجود المواد والخط والإعداد الآمن والحالة؛ لا يختبر اتصال خدمة الصوت أو اكتمال اعتماديات المحرك أو مزامنة المشاهد. يلزم تشغيل اعتماديات المشروع المقفلة في بيئة الإنتاج، واختبار `ar-SA-HamedNeural`، وضبط توقيت المشاهد والترجمة بعد توليد الصوت قبل اعتبار الفيديو النهائي جاهزًا. لا تغير `draft` إلى `approved` إلا بموافقة صريحة من المستخدم؛ ولا يجيز اعتماد الإنتاج نشر الفيديو.
